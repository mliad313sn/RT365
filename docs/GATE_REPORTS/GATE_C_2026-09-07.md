## 3. Independent re-verification of the mandated claims

The full table is in GATE_B_2026-09-07.md §3 (same probes, same commit). Gate-C-relevant detail on the two findings that drive the verdict:

**IVA-01 — Kill Switch not enforced in the execution plane (probe C3).** Sequence: (1) `decide()` returns APPROVED for a valid intent; (2) an `OrderCommand` is built exactly as `TradePipeline._authorise_and_execute` builds it; (3) `KillSwitchService.activate(ACCOUNT, acct-sim-001)` by a human SRE — the account becomes HALTED, resting orders are cancelled, the executor lease is preempted and released; (4) one second later an executor named `executor-restarted` calls `LeaseStore.acquire()` — it succeeds because the switch held no lease of its own; (5) `ExecutionGateway.submit(command, …)` inside the CONTROL plane — the sim broker ACKNOWLEDGES the order. `broker_submissions_received == 1`, `killswitch.active()` non-empty. Reading `gateway.py` confirms the only checks are plane, idempotency key, live-order-per-intent, fencing token and adapter presence. In the single-process sim the pipeline authorises and submits in one call stack, so this window is not reachable through `run_intent()`; on the ADR-005 bus topology (outbox `replay()` exists) it is. The blueprint's non-negotiable is that the Kill Switch supersedes everything [Source: 00].

**IVA-02 — Gateway trusts the command (probe B4).** A command with `decision_id="dec_forged"`, `authorised_by="FORGED"` and no risk decision anywhere was ACKNOWLEDGED when submitted from a caller that entered the CONTROL plane with a valid lease. `OrderCommand` (order.py lines 33-55) has no signature; the gateway never consults a decision store. THREAT_MODEL T-08 lists "signed intents" as the control; it is not implemented for commands.

**IVA-03 — position cap evadable via resting orders (probe J7).** `chk_caps` computes `projected_qty = position + signed_qty` from positions only (engine.py lines 296-310); `_book()` includes open orders but is used only by exposure/concentration/leverage/correlated checks. Two concrete evasions passed `max_position_per_instrument` at APPROVED outcome with the book caps loosened to isolate the check.

**IVA-04 — strategy owner can approve own strategy's intent (probe J3).** `approvals.enqueue(vi, decision, now=now)` at pipeline.py line 133; `ApprovalItem.strategy_owner_id=None`; `quant.fixture` approved as PORTFOLIO_MANAGER.

Builder tests read for coverage: TC-AP-004 (Kill Switch after approval) exercises only the pipeline re-decision at ACCOUNT level; TC-EX-* never submit a command after activation; TC-RK-017 covers resting buys against gross exposure only; TC-AP-002 covers maker ≠ checker but not strategy owner. These are happy-path-adjacent gaps, not failing tests.
