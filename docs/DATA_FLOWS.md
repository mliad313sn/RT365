## 0. How to read this document

- Every statement carries a tag: **[Source: NN]** (blueprint section as transmitted by the repository artefacts), **[Committee]** (the owner's or a council's reasoning from the artefacts), **[Open]** (unresolved, with the register item that settles it). No statement here is self-certified and nothing here approves anything [Committee].
- **Control rule (C-DF-1..C-DF-5, ARB §3.4):** a control appears in the *Controls* column only if the *Implemented by* column names a code path **and** the *Tests* column names a test id. Everything else is written as a **target** with its [Open] reference, so that no target can be read as evidence [Committee].
- **Number rule:** this document contains no throughput, latency, storage or cost figure. Capacity figures live in docs/CAPACITY_MODEL.md and are [Open] until measured [Committee].
- **Columns.** *Source → Sink* names the producing and consuming component; *Plane(s)* the trust planes crossed [Source: 03, 04]; *Carrier* how the data actually travels (in-process call, store file, bus, HTTP, file system); *Classification* is **proposed by the Data Architect and decided by the Security & Privacy Board** — every cell in that column is a proposal until the Board's classification review is recorded [Open: O-106, O-129]; *Implemented by* names modules and symbols (not line numbers, which drift) read at commit `ded8e17` on 2026-09-08 [Committee]; *Status* separates what dev/sim implements from what is a target.
- **Evidence rule added in v1.2.** The cells corrected in v1.2 cite `path:line` read at commit `442cebd`, because a correction of fact must be checkable at the place it was checked; everywhere else the module-and-symbol convention of v1.1 stands. A line citation is evidence of what the tree said at that commit and of nothing else; where no code implements a statement, the statement is marked [Open] rather than softened [Committee].
- **Scope of the evidence.** Everything marked "implemented dev/sim" is evidenced only in the dev and sim environments; no market, broker capability, data entitlement, regulatory permission or production behaviour is asserted anywhere in this document [Source: 00] [Open: O-12, H-08, R-05, R-06].
- Residency and transfer per tenant are maintained in docs/PRIVACY_IMPACT.md [Source: 06]; §4 carries the pointer and the market-data residency rule decided in D-056.

- Market data is stored in the tenant's regional cell, knowledge time is enforced at the store, and there is no cross-cell market-data replication (D-056, ADR-007) — DF-01, DF-02 [Committee].
- Cross-cell traffic is limited to audit replication and the portfolio roll-up (ADR-007); the roll-up carrier is a target [Open: R-05].
- Residency enforcement at storage — encryption, region pinning, key location — does not exist yet [Open: F-7, H-05].
- Knowledge time is never later than decision time: a read whose `as_of` is after the knowledge time raises `LookAheadViolation` at the store rather than by convention (DF-01) [Committee].
