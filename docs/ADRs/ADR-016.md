# ADR-016 — Delivery agents generated from the role prompts, one MCP transport, and a fail-closed installable distribution
**Status:** Proposed · **Date:** 2026-09-07 · **Deciders (ARB):** ARB, Security & Privacy Board (agent guard, MCP transport), Executive Steering (Product Owner seat) · **Consulted:** Product Owner, MCP Security Agent, Security Architect, SRE Lead, Backend Lead · **Provenance:** [Source: 00, 04, 13, 16] / [Committee] / [Open: O-23 artefact signing, O-35 tool registration, O-57 ratification, O-58 harness support of agent hooks]

Author: Delivery Orchestrator (AI) · Reviewer: pending (MCP Security Agent, Security Architect) · Approver: pending (ARB). Written with the commit that introduced the mechanisms; it does not approve them.

## Context
The kit described 28 committee roles, six gates and fifteen build epics as prompts, but nothing turned them into agents an engineer could invoke, `goals/build/` did not exist although CLAUDE.md told every coding agent to read it, no MCP server existed for an agent host to reach the six tools other than the BFF route, and the product could only be run from a source checkout with `PYTHONPATH` set by the Makefile. The `/goal` instruction of 2026-09-07 asked for a Product Owner, every agent and MCP server the delivery needs, and an installation package with an executable.

## Decision
1. **Product Owner seat.** A 1st-line role accountable for completeness and executability (`goals/00_product_owner.md`, `docs/PRODUCT_OWNER.md`, `Role.PRODUCT_OWNER` with read-only permissions). It prioritises and accepts; it never approves risk, compliance, security, models, gates or its own records.
2. **Agents are generated, never hand-written.** `scripts/generate_agents.py` renders one Claude Code agent per prompt in `GOAL.md`, `goals/00..28`, `goals/build/E01..E15` and `goals/gate_*` into `.claude/agents/`, with a roster (`roster.json`) of the paths each agent may edit (owned artefacts + shared ledgers; 3rd line: reports and RAID only; builders: their epic's code, tests, evidence, ADRs and ledgers). A PreToolUse hook (`scripts/agent_guard.py`) denies edits outside the roster. `--check` runs in CI so the prompts stay the single source of truth.
3. **One MCP transport.** `mcp_servers.stdio` implements the MCP stdio protocol over the existing `ToolRuntime.call`; `rt365 mcp-serve --env sim` binds a sim identity in the host process; `.mcp.json` declares only `rt365-sim`. No resources, prompts or sampling; the module obeys the same import ban as the rest of `mcp_servers`.
4. **Distribution.** A `rt365` console script (`apps/cli/rt365_cli`) with `version | check | probe | serve | mcp-serve | certify-broker`; `rtcore.resources.resource_root()` resolves the policy bundle (explicit `RT365_HOME` → frozen bundle → installed bundle → source checkout) and fails closed when the signed registry is absent; `scripts/build_package.sh` builds wheel and sdist with the bundle; `installer/rt365.spec` builds a one-file executable; `.github/workflows/release.yml` builds Linux, macOS and Windows (`rt365.exe`) binaries, smoke-tests each from another directory including the fail-closed rules, and attaches them (unsigned, with SHA-256) to tagged releases.

## Alternatives considered (minimum two)
| Alternative | Pros | Cons | Why not |
|---|---|---|---|
| A. Generated agents + roster guard + stdio transport + fail-closed distribution (chosen) | prompts stay authoritative; segregation is machine-checked; one code path to the tools; same posture in every artefact | guard is bypassable through Bash by design (harness hook, not a control); hooks in agent frontmatter depend on harness support (O-58) | Chosen; CODEOWNERS/CI remain the controls of record |
| B. Hand-written agent files | flexible per agent | drift from goals/, no segregation check, 51 files to maintain | Rejected |
| C. HTTP/SSE MCP server inside the BFF | one process | opens a network listener with tool access; identity would come from headers (R-06) | Rejected for dev/sim; revisit with IdP (E01) |
| D. Docker image only, no installer or executable | reproducible | does not answer "installation package and .exe"; excludes Windows operators without Docker | Rejected as the only channel (compose stack kept) |
| E. Product Owner = Product Director (no new seat) | fewer roles | blueprint's Director owns scope, not delivery acceptance; the instruction asked for an owner of completeness/executability | Rejected; seats may be held by one person until staffed |

## Consequences
- CI gains `make agents-check`; `make all` includes it. Editing a prompt requires regenerating agents.
- The installed and frozen builds carry `mcp/policies`, `observability/*.yaml`, `services/risk/policies` and `apps/web/static` verbatim; a tampered bundle fails the registry signature check.
- `rt365 mcp-serve` issues an 8-hour sim identity (default TTL is 5 minutes); acceptable only because the environment is sim and the registry is a fixture (R-47).
- Executables are unsigned until O-23; installers verify SHA-256 only.
