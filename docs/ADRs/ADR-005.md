## Context
Kafka-compatible bus and schema registry are in the reference stack.

## Decision
Adopt a Kafka-compatible bus with schema registry; all events versioned; consumers idempotent.

## Alternatives considered
(a) Direct HTTP calls — rejected: no replay/outbox. (b) Bus without registry — rejected: schema drift.

## Consequences
Operational cost; replay for audit and backtest.

## Consumer assumption (added 2026-09-08, ADR-018 / BUILD_E07 C-8)
One consumer per idempotency key at a time (partition semantics): `Inbox.process_once` checks, runs, then stores and holds no claim row, so two consumers processing the same key concurrently could both run the work. The bus adapter must assign each key to exactly one consumer; a claim row is required before any topology that relaxes this. [Committee]
