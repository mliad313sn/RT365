# ADR-009 — Service framework: FastAPI + Pydantic v2 for the typed service layer
**Status:** Accepted 2026-09-08 by the Product Owner agent under D-040 on the ARB chair's APPROVE WITH CONDITIONS (D-055; conditions: TC-ARC-001 import ban in place; Execution-plane host re-evaluated at Gate C on measured latency, O-86; fastapi/starlette/uvicorn under the gating SCA) · **Date:** 2026-09-07 · **Deciders:** ARB · **Consulted:** Backend Lead, Integration Architect, Security Architect · **Provenance:** [Source: 03 "FastAPI or typed service framework"] / [Committee]

## Context
Blueprint 03 lists FastAPI or an equivalent typed framework. The control envelope depends on strict, schema-first models (unknown fields rejected, Decimal money, frozen records) more than on the HTTP layer.

## Decision
Pydantic v2 `StrictModel` (frozen, `extra="forbid"`) for every contract and record; FastAPI for the BFF and service edges. The deterministic engines (`risk_engine.decide`, `compliance_engine.decide_eligibility`) are plain pure functions with no framework dependency so they can run in any host (service, consumer, backtest, replica test).

## Alternatives considered (minimum two)
| Alternative | Pros | Cons | Why not |
|---|---|---|---|
| FastAPI + Pydantic v2 (chosen) | strict schemas, OpenAPI generation, async, large ecosystem | Python GIL for latency-critical paths | engines are pure and portable; latency baselines [O-03] decide later whether the gateway moves |
| Go (typed, gRPC) | latency, static binaries | two languages for one control envelope; slower iteration on schema evolution | revisit at Gate B capacity model for the Execution plane only |
| Django REST | batteries included | heavier, ORM-centric, weaker strict-schema story | not needed for a queue/event-driven core |

## Consequences
Single language for engines and edges; the OpenAPI document remains the contract (`test/contract/test_openapi_alignment.py` fails on drift). Performance envelope to be measured (PERFORMANCE_PLAN).

## Controls and tests affected (RTM rows)
FR-11, FR-15 (engine purity), NFR-DET-01; TC-RK-001 (replica determinism in a separate interpreter).

## Threat-model delta
None to boundaries; B2 (BFF↔services) inherits FastAPI dependency hygiene — SCA gate (NFR-SEC-02).
