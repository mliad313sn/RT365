# ADR-015 — The execution gateway as last control point: command authorisation and permission oracle

## Context
The Independent Validation Agent showed two paths around the control plane at the only component with a broker route. **V-C1:** the gateway consulted neither Kill Switch flags nor account mode; a genuinely APPROVED command submitted after an ACCOUNT-level activation, with a re-acquired lease, was acknowledged by the (simulated) broker. The synchronous pipeline re-decides at approval time, but the bus/outbox topology of ADR-005 delivers commands asynchronously, so "decided before the switch, executed after" is a real window. **V-C2:** `OrderCommand` carried no proof of origin and `decision_id` was never checked; a caller that had merely entered the CONTROL plane submitted a forged command that was acknowledged. Blueprint 03 requires that the Kill Switch, halts and human override supersede everything, and blueprint 04 that only the risk/approval path can authorise execution.

## Decision
1. **Command authorisation.** `OrderCommand.authorisation` is an HMAC-SHA256 over `OrderCommand.authorised_digest()` (every field except the MAC). `execution_gateway.authorisation.CommandAuthoriser` signs in the pipeline (`TradePipeline.sign_command`) and verifies in the gateway (`_assert_authorised`). The key is created in the composition root (`build_sim_platform`) and handed only to those two callables; no MCP/AI component, tool, handler, BFF route or agent identity holds it. An unsigned or altered command raises `CommandNotAuthorised` (a `ControlDenied`), audits `order.command.unauthorised` and raises S1 `execution.unauthorised_command` (auto-action `killswitch_account`).
2. **Permission oracle.** The gateway takes `execution_permitted(command, now) -> reason | None` and calls it at `submit()` after the fencing check (the last gate before the adapter) and at `retry_submit()` before any resubmission. The composition root's oracle applies, in precedence order: Kill Switch scope (`KillSwitchService.blocks` at platform/tenant/account/strategy/asset/venue) > account HALTED or non-ACTIVE trading status > tenant match > execution target consistent with the account mode > decision provenance (the decision is known to the control plane, belongs to this intent and policy version, and is APPROVED — or REQUIRES_HUMAN_APPROVAL with an APPROVED approval record for that decision). A denial raises `ExecutionBlocked`, audits `order.command.blocked` and raises S1 `execution.blocked_at_gateway`.
3. **Fail closed by construction.** A gateway built without an authoriser or without an oracle submits nothing (`CommandNotAuthorised("... fail closed")`).
4. **Not decided here.** Asymmetric signing with an HSM/KMS-held key and rotation (O-53); externally anchored audit heads (O-54); the durable decision index behind the provenance check (R-05).

## Alternatives considered (minimum two)
| Alternative | Pros | Cons | Why not |
|---|---|---|---|
| A. Verify at the gateway with a control-plane MAC and an injected oracle (chosen) | Last component before the broker enforces the invariant; independent of transport; testable in-process | Shared key in dev/sim; oracle state must be as fresh as the Kill Switch store | Chosen; O-53 lifts the key limitation |
| B. Trust the Control-plane network boundary (status quo) | No code | IVA forged a command from inside the boundary; Kubernetes policy is not an authorisation | Rejected |
| C. Gateway subscribes to Kill Switch events and keeps a local flag | Decoupled | Eventual consistency window is exactly the V-C1 failure | Rejected as sole mechanism; acceptable as a cache in front of the oracle |
| D. Re-run the full risk decision inside the gateway | Strongest check | Duplicates the engine in the Execution plane; the gateway would need market/account snapshots it must not hold | Rejected |

## Consequences
- The pipeline must sign every command; tests that construct commands by hand must re-sign through `platform.pipeline.sign_command` (TC-EX-003, TC-EX-007 updated).
- `order.command.v1` gains the `authorisation` field (schema regenerated, Integration Architect review pending).
- Two new S1 alerts in `observability/alerts.yaml` and docs/ALERT_CATALOG.md.
- The oracle's decision index is in-memory in dev/sim (R-05).

## Controls and tests affected (RTM rows)

## Addendum (2026-09-07, after REVALIDATION_2026-09-07_0cbc895)
- Authorisation is a short-lived one-shot grant: refused when `authorised_at` is older than `COMMAND_MAX_AGE` (5 min) or in the future, when the MAC was already consumed, or when the `decision_id` already produced an order (`_by_decision`); the oracle also refuses intents whose lifecycle state is not AUTHORISED/SUBMITTED/ACKNOWLEDGED/PARTIALLY_FILLED (IVA-21, D-033).
- The MAC is verified before the idempotency inbox answers (IVA-25); the digest is canonical JSON (IVA-20); the gateway holds a `CommandVerifier` without a sign method (IVA-22, partial: in-process memory is not a boundary, O-53).
- An order adopted on retry that is live at the broker is cancelled at once when execution is blocked; a failed cancel raises S1 `execution.live_under_block` with auto Kill Switch on the account (IVA-19, D-032).
- `execution.unauthorised_command` no longer triggers an automatic Kill Switch because the account id in a forged command is attacker-chosen (IVA-23, D-034).
