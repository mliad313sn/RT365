# ADR-017 — Meridian IT-PMO as the project-lifecycle system of record for the portfolio view
**Status:** Accepted 2026-09-08 by the Product Owner agent under D-040 (D-049; the repository ledgers stay the source of truth for everything a gate reads, and Meridian's four-gate phase machine is not used for authorisation) [Open: O-73..O-76]. **The decision-log entry is the truth; this line quotes it and does not create it** [Source: 13, CLAUDE.md] · **Date:** 2026-09-08 · **Deciders:** Product Owner (D-040); ARB chair and CAB chair consulted · **Provenance:** [Owner instruction 2026-09-08: "use mliad313sn/Meridian to manage all the project lifecycle"] / [Verified: Meridian 5.9.0 at commit 77c4b49, 449 tests pass, loaded on 2026-09-08] / [Open: O-73..O-76]

## Context
The delivery kit keeps its lifecycle in Markdown ledgers (backlog, RAID, decisions, missing actions, gates, evidence index). They are auditable and diff-able but give no portfolio view, no meeting rhythm generated from the state, and no earned-value or critical-path arithmetic. The owner asked to manage the whole lifecycle with Meridian IT-PMO (https://github.com/mliad313sn/Meridian, Apache-2.0, self-hosted, PostgreSQL or PGlite), which provides exactly that: projects with stage gates, RAID, change control, meetings whose agendas are generated from the portfolio, an append-only audit trail and an archive/restore path.

## Decision
1. **Two systems, one truth.** The repository ledgers remain the source of truth for anything a gate reads (they are versioned with the code and evidenced by CI). Meridian is the **portfolio and rhythm system**: it carries the programme, one project per epic, the gate milestones, the RAID register, the Product Owner's weekly with its decisions and actions, and the audit trail of who changed what.
2. **One-way, idempotent sync.** `scripts/meridian_sync.py` (`make pmo-sync`) loads the ledgers into Meridian through its session API; it creates what is missing, updates milestone criteria, never deletes. Credentials come from the environment; the public demo credentials are refused unless explicitly allowed for a seeded demo instance.
3. **Mapping.** Programme `RBT`; site `RTX`; project `RBT-GOV` with milestones Gate A–F (acceptance criteria = the gate's exit evidence; Gate A marked done after D-048); projects `E01..E15` with the accountable lead as project manager and the first gate as finish horizon; RAID rows O-/R- (open) → Meridian RAID on the governance project, typed Risk/Issue/Assumption/Dependency; decisions D-0nn → meeting decisions; open human acts H-nn → meeting actions owned by the Product Owner. Dates are planning placeholders until O-17.
4. **Not decided here.** Writing back from Meridian to the ledgers (Meridian's public API is read-only by design); replacing the ledgers with Meridian; running Meridian as a service (backup, second instance, security policy — the three operational findings its own SECURITY.md lists).

## Alternatives considered
| Alternative | Pros | Cons | Why not |
|---|---|---|---|
| A. Meridian as portfolio/rhythm system, ledgers stay the truth, one-way sync (chosen) | portfolio view, generated meetings, audit trail; no loss of CI-evidenced ledgers | two places to look; sync must be re-run after ledger edits | Chosen |
| B. Meridian as the only system, ledgers retired | one place | gates read files that CI evidences; Meridian has no write API for the agents, no RTM/quartet concept | Rejected |
| C. GitHub Projects/Issues only | native to the repo | no gates, EVM, RAID typing, meeting generation, audit trail with before/after images | Rejected |
| D. Commercial PPM (Planview, Smartsheet) | vendor support | cost, lock-in, no self-hosting, no source | Rejected for this stage |

## Consequences
- `make pmo-sync` after every ledger change; the Product Owner's weekly is opened in Meridian with the decisions and actions of the week.
- Meridian's fixed four-gate model (Mandate, Design authority, Readiness, Benefits) coexists with our six gates as milestones; Meridian's phase machine is not used to authorise environments (our gates do). Improvement points for Meridian are in docs/PMO_MERIDIAN_ASSESSMENT.md.
- Findings raised against Meridian while loading (O-73..O-76) are offered upstream.

## Controls and tests affected
None of the trading controls. test/contract/test_meridian_sync.py covers the ledger readers and the credential rule. Evidence: docs/PMO/meridian_sync_2026-09-08.json, docs/PMO/*.png.
