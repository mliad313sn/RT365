# ADR-010 — In-process composition root and in-memory stores for the dev/sim environment
**Status:** Proposed · **Date:** 2026-09-07 · **Deciders:** ARB · **Consulted:** Cloud Architect, SRE Lead, IVA · **Provenance:** [Committee, derived from 00 environment ladder and 03 stack]

## Context
Before any external dependency exists (brokers, licensed data, vault, Kafka, Postgres are all human-gated in docs/MISSING_ACTIONS.md), the control envelope must be exercised end to end so that determinism, idempotency, fencing, Kill Switch and audit evidence exist for Gate B/C.

## Decision
`apps/web/web_bff/platform.py` wires every bounded context in one process with in-memory stores (audit chain, lease store, outbox/inbox, bitemporal store, ledger). Plane boundaries are still enforced in-process by `rtcore.planes.PlaneGuard`, mirroring the Kubernetes network policies. Each store has a narrow interface so the Postgres / Kafka-compatible / WORM-object-store adapters replace it without touching engine code. The environment tag `sim` is stamped on the policy, registry and evidence.

## Alternatives considered
| Alternative | Pros | Cons | Why not |
|---|---|---|---|
| In-process + in-memory (chosen) | fastest path to control evidence; deterministic tests; no infra | not the production topology; durability not proven | gate ladder authorises only dev/sim now; durability is a Gate C exit criterion |
| docker-compose with Postgres + Redpanda from day one | closer to production | infra provisioning is a human act (H-05); slower tests | provided as the next step (infra/docker-compose.yml) |
| Mock engines | trivial | proves nothing | rejected |

## Consequences
Every Gate C claim about durability, exactly-once under real redelivery and failover must be re-evidenced on the deployed topology (RAID R-05). The in-process guard is a unit-level proof, not a network-level proof (TC-NET-003 also checks the manifests).

## Controls and tests affected
NFR-CON-01, NFR-RES-01a, NFR-AUD-01; TC-EX-*, TC-AUD-*, TC-NET-*.

## Threat-model delta
None; B3/B4 enforcement moves from process to network at deployment, tested by scripts/check_network_policies.py.
