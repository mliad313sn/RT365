## Context
Blueprint 03 names a Next.js/TypeScript PWA. The dev/sim build needs a console that proves the information hierarchy (risk before profit, reason-code dictionary, typed confirmation for the Kill Switch, maker-checker approvals) without a JavaScript build pipeline.

## Decision
`apps/web/static/index.html` is a dependency-free dashboard served by the BFF, wired to `/v1/status` (whose keys are ordered 1..7 by the hierarchy), `/v1/approvals` and `/v1/killswitch`. It is a placeholder for the E10 PWA; WCAG 2.2 AA verification by the Accessibility Lead has not been performed.

## Alternatives considered
| Alternative | Pros | Cons | Why not |
|---|---|---|---|
| Static page served by BFF (chosen now) | zero build, proves API shape and hierarchy | no component model, no offline PWA, limited a11y tooling | sufficient for dev/sim; not a Gate F artefact |
| Next.js PWA now | matches blueprint | npm supply chain, build pipeline, design system all pending | scheduled under goals/build/E10 |
| Server-side templates (Jinja) | simple | same limits as static | no advantage |

## Consequences
E10 stories must replace the page while keeping `/v1/status` ordering as the contract for "risk above profit". Accessibility evidence remains [Open] until the Accessibility Lead signs.

## Controls and tests affected
FR-16, NFR-A11Y-01; TC-E2E-J03/J05/J06 exercise the API the console uses.

## Threat-model delta
B1 user↔BFF: dev header authentication is client-asserted and must be replaced by IdP/MFA sessions before any shared environment (RAID R-06).
