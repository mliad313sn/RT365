## 0. Rules that govern every cell [Committee]

- **A cell is filled only with a measured or quoted value and its evidence id. A blank cell is [Open], never an estimate** (ARB C-13-1, IVA-B-07). "Cell" in this rule means a table cell; the deployment sense is §1a.
- **No number in this document is a target.** The ARB recommends the **structure** at Gate B; **baselines are accepted at Gate C and targets at Gate E** (O-03). This replaces v0.1's "the ARB signs the model once baselines exist", which contradicted the document's role as Gate B exit evidence and D-057 (C-CM-1).
- A value read out of the source code is a **parameter**, not a decision and not a target; §7 lists them separately so that nobody later cites a code default as if it were a decided value (C-CM-3).
- **Capacity is never bought with a plane bypass** [Source: 03, 04] [Committee]. Every shed, autoscale and failover statement below is subject to the topology: the Analytics plane has no route to the Execution plane or to brokers, and no capacity argument may create one. Load is shed in the Analytics plane; the Control and Execution planes fail closed instead of shedding. The written form of this rule is enforced by `scripts/check_network_policies.py` rule 2 (no Analytics egress to `plane=execution`, `plane=security` or any `ipBlock`) and rule 7 (**no egress rule anywhere may use `0.0.0.0/0` or `::/0`**; the Execution plane's broker route is explicit CIDRs per certified adapter), tested by TC-NET-001..004.
- **Capacity is never bought by widening an egress rule either** [Committee] [Source: 04]. A throughput or cost argument that replaces per-adapter broker CIDRs with a wider block, or that adds an `ipBlock` to a non-Execution namespace, is refused by the checker before it is argued; the Execution namespace is the only namespace that may hold an `ipBlock` at all.
- **Every "per cell" statement in this document rests on ADR-007 (regional deployment-cell topology), whose status is still `Proposed`** (docs/ADRs/ADR-007.md:3) [Committee]. It is no longer absent from the decision log: **D-069** records the delegate's acceptance of the amended text (rev.1) **as the version to decide on, not the decision itself**, because the Cloud Architect's review of rev.1 is owed (docs/DECISION_LOG.md:77). The amendment separates the invariant — the deployment cell as failure domain, a closed directional list of what may cross it, and the audit witness living outside the cell it witnesses — from the provisioning rule "one cell per venue cluster", **whose key phrase is defined nowhere in this repository**. Read every "per cell" below as "per deployment cell *if* ADR-007 is decided as proposed" [Open: ADR-007 status, O-177]. "Cell" here always means a **deployment cell**, never a `JurisdictionCell` [Source: docs/NFR.md:38].
- A CI test-suite timing is not a capacity baseline. ADR-018 records the suite at 9.5 s before and 8.9 s after on the memory default; that figure is deliberately **not** carried into this document, and no figure of that kind may be cited as a platform baseline [Committee] (COUNCIL_2026-09-08_gate_B_arb_docs.md §4.1).
- Every statement is tagged [Source: NN], [Committee] or [Open]. No cloud price, vendor capability, provider tick rate, licence term, throughput or latency is asserted anywhere in this document [Source: 00].
- Nothing here authorises an environment. **No cell is provisioned** — §1a states exactly what does and does not exist in `infra/` [Open: H-05, A-6, B-15] (C-CM-5).

## 1a. Cell topology and what a cell is provisioned with [Committee] [Source: 03, 04] — Cloud Architect

**What a cell is.** One regional cell per venue cluster; the cell is the failure domain; cross-cell traffic is limited to **audit replication and the portfolio roll-up**; market data does not leave its cell (ADR-007 — **`Proposed`**, §0). Each cell contains the five plane namespaces and the plane network policies. NFR-RES-01 (cells as failure domains, active/standby execution ownership) and NFR-DR-01 (RPO/RTO per cell) are stated against this shape.

**What exists in `infra/` today**, read at this commit [Committee] — this is an inventory of the repository, not of any environment:

| Object | Count / state | Where |
|---|---|---|
| `Namespace` | 5 — `analytics`, `control`, `execution`, `security`, `edge`, each labelled `plane:` | `infra/kubernetes/namespaces.yaml` |
| `NetworkPolicy` | 9, in 5 files (analytics, control, execution, mcp-servers, security); default-deny per plane plus explicit allows; broker egress is one placeholder `ipBlock` in the RFC 5737 documentation range, filled per certified adapter at deployment | `infra/kubernetes/network-policies/` |
| Any other Kubernetes object kind | **none** — no Deployment, StatefulSet, Service, HPA, ResourceQuota, LimitRange, PodDisruptionBudget, StorageClass, PersistentVolumeClaim, PriorityClass or Ingress exists | — |
| Terraform / Pulumi modules | **none** — "modules are added here once the cloud provider is chosen"; provisioning cloud accounts, vault/KMS, clusters and the egress gateway is a human act | `infra/iac/README.md`, H-05 |
| Dev/sim compose stack | 1 file (`bff`, `postgres`, `redpanda`); it is the dev/sim target for the Postgres and Kafka-compatible adapters and **connects to no broker**; the `redpanda` service runs but **no code publishes to or consumes from it** (§1 gap 3); it is not a cell and its resource settings are not a capacity statement | `infra/docker-compose.yml` |
| Image definitions | 1 — the only image definition in the tree; the compose stack builds the BFF from it (F-10) | `infra/Dockerfile.bff` |

**Therefore, from this seat, explicitly [Committee]:**

- **No cell is provisioned.** No cloud account, region, cluster, node pool, instance type, storage class, disk class, bus, vault or egress gateway is chosen or created. A reader must not infer a deployed component from this document, from `docs/CONTAINER_DIAGRAM.md`, or from the compose file [Open: H-05, A-6, B-15].
- **A cell therefore has no capacity.** There is no CPU, memory, IOPS, storage or network figure to state, because there is no thing to state it about; every per-cell dimension in §1 is a *shape*, and the numbers arrive only after H-05 (provisioning) and the Gate C baselines.
- **The plane boundary is real; the plane capacity boundary is not.** The network policies are enforced and tested (TC-NET-001..004), so no plane can *route* around another. But without ResourceQuota or LimitRange objects, nothing stops one plane's workload consuming a shared node's CPU or memory — noisy-neighbour containment is claimed by the cell topology and implemented by nothing today. Capacity isolation between planes is a Gate C design item, not a Gate B claim [Open].
- **The first cell's contents are the first capacity question a human must answer**, and it is not an architecture question: how many cells, in which regions, at what size, is H-05 plus Q-11-1 (the region whose price list applies) plus D-043 (one venue, cash equities/ETFs, first-party account) — see §8.
- **Cross-cell cost is not zero.** Audit replication is cross-cell **by design**, so cross-cell egress is a permanent cost term of this architecture, not an exception; it has no measurement and no quote (§2, §4a) [Open: O-87, H-05].

## 4a. Recovery consequences: two O(n) checks on the start-up path [Committee] [Source: 03, 10] — Cloud Architect, O-18

This section is a **dependency statement, not a measurement**. It contains no number and proposes none.

Two verifications are now unconditional on process start, and both are linear in history:

- the **control store** replays its hash-chained journal at open and compares it with state — O(journal rows), and the journal is never compacted (ADR-018 §Consequences, O-111, O-55);
- the **audit store** verifies its whole chain at open, and the anchor chain is re-verified on every read **and on every publication, which is on the append path (F-04, §4)** — O(events) plus O(anchors), with anchors accumulating without compaction (ADR-020 §Consequences, O-133).

Both are also **O(n) in memory, not only in time (F-05)**: the control-store verify materialises the journal (libs/core/rtcore/store.py:358) and the audit store keeps every event resident for the life of the process (services/audit/audit_service/store.py:235, 278-282). Memory is the term that turns a slow restart into a restart that never finishes, and no `ResourceQuota` or `LimitRange` exists anywhere to size it against [Open: O-156, O-160].

Both are the correct fail-closed design and neither should be weakened for speed: recovery is *restore then verify*, and disabling the check is never the fix (O-134). Their capacity and DR consequences are:

| Consequence | Why | Register |
|---|---|---|
| **The start-up verifications alert before they refuse — and that is new (F-02).** When the SRE Lead reviewed v0.2 this was false: both checks ran *inside* the store constructors, and the composition root wired the alert sink a few lines **later**, so the two failures with the largest blast radius on this platform emitted **no** alert, ran **no** auto-action and appeared only as a process that would not start. Today the router is the **first** thing composition builds (apps/web/web_bff/platform.py:756), a single start-up correlation id is minted for the attempt (platform.py:757), `open_store` announces the catalogued alert and then **re-raises unchanged** (platform.py:759-785), and `AuditStore` takes the sink **at construction** rather than afterwards (platform.py:808; services/audit/audit_service/store.py:231, 261-267). **Two limits stay, and neither may be softened:** the `killswitch_platform` auto-action is **not yet bound** at the open-time checks (it is bound at platform.py:1377, long after the stores are opened at platform.py:791-810), so an unbound auto-action raises `alert.autoaction_failed` (S1) instead of the halt (observability/rtobs/alerts.py:101-115) — the process refuses to start anyway, which is the stronger outcome, and the platform-wide verification against the published witness runs later, after the auto-actions are bound (platform.py:1421-1422); and **no notification component exists**, so an alert is dispatched to in-process channel records and nothing pages a human (observability/rtobs/alerts.py:56, 70-87; observability/slis.yaml:121-126). Detection is therefore **an in-process alert plus a process that never becomes ready** — a readiness-based page is still the thing that finds this, and it is owed before shadow | a control whose failure cannot reach a human is not ready to be relied on; the code half is done, the delivery half is not | [Open: SRE-R5 proposed, O-15] |
| **Restart time grows with history, and restart time is how long an account has no executor.** The executor recovery path is lease expiry or preempt → store open with `verify()` → cancel-on-restart, and **an in-flight order is cancelled, not resumed** (F-09, §3) | the verify is on the critical path of every restart, planned or not | [Open: O-111, O-28, O-33] |
| **Cell failover inherits both checks, not one.** A standby cell that takes over must open a control store *and* an audit store, each verifying its own history, before trading can reopen. `docs/DR_PLAN.md` v1.2 §3 now states that step as an **ordered unit** — restore the audit store, confirm its length against the last published anchor, attach the witness, run an explicit **published** verification, only then seal — because the natural mistake (a restored chain shorter than the surviving witness) verifies as `AUD-CHAIN-TRUNCATED` and reaches `killswitch_platform`, halting the platform being recovered (D-01). The step is an unmeasured O(n) operation in **time and memory** on the recovery-time path | the DR plan's order of restoration puts the audit verification ahead of the control and execution planes | [Open: O-18] |
| **RPO/RTO candidates cannot honestly be proposed yet.** An RTO is a promise about a path whose two longest unmeasured steps are these verifications plus the restore itself; an RPO for the audit trail depends on the cross-cell replication lag of §4, which has no measurement and no provisioned replica | O-18 is therefore blocked on O-111, O-133 and a drill, not merely on a human choosing a number | [Open: O-18, O-111, O-133] |
| **The DR drill must measure, not assert — and against three lengths, not one (F-11).** The drill that settles O-18 records **control-store journal rows**, **audit chain events** and **anchor records** separately (they grow at different rates: anchors accrue one per seal plus one per `anchor_every` events, so the third is not derivable from the second), plus the **wall-clock split** across restore · control-store `verify()` · audit-chain verify · anchor verify · reconciliation-before-reopen, plus **peak resident memory** per verification, plus the environment and disk class (**none is chosen**, §1a), plus whether the cell was fresh or aged. A single total conceals which phase to attack; a single "length" invites the reader to assume the three move together | a drill on a fresh cell measures the best case and reads as the general case; the record requirement is carried in docs/DR_PLAN.md §6 and docs/INCIDENT_RESPONSE.md RB-14 | [Open: O-18, H-05] |
| **Compaction and retention are the lever, and neither exists.** Journal compaction (O-111, O-55) and anchor/audit retention (O-133, O-135) are the only ways to bound these two costs, and both are decisions with integrity and legal consequences, not tuning knobs | shortening history to speed recovery is a change to the evidence, so it is the Security & Privacy Board's and Compliance's decision as much as the SRE Lead's | [Open: O-111, O-133, O-135] |
| **Availability consequence of the fail-closed witness — corrected (F-01).** A lost, stale or corrupt witness **does not halt the platform**: `audit.anchor_missing` is S1 with auto-action `none`, trading continues while a human restores the witness (docs/ALERT_CATALOG.md:19). A witness this store **recorded and can no longer find** stops the store from opening (`WitnessLostError`; a refusal, not a Kill Switch, because a Kill Switch activation would write to the store under suspicion — D-068), and the recovery is an attested operator act, not a restart. The platform-wide halt belongs to a **chain** failure — `audit.chain_verification_failed` → `killswitch_platform` — which is the largest blast radius of any catalogued alert and was **inherited with a build rather than decided** [Open: O-137]. The time to restore and re-verify is unmeasured in all three cases, and the restore-then-verify path is the only recovery: disabling the check is never the fix and no flag exists to do it (O-134, O-165) | a capacity model that credits a control with a consequence it does not have would tell a Gate B reader that a control exists which does not | [Open: O-18, O-134, O-137] |

`docs/DR_PLAN.md` carries the same dependency; its RPO/RTO candidates stay [Open: O-18] until these measurements and a drill exist. **A target is not evidence, and a drill on an empty system is not a baseline** [Committee].

## 5. Measurement plan — all nine SLIs of `observability/slis.yaml` [Committee] — C-CM-4

No target is set for any SLI; `slis.yaml` carries `target: null` for all nine, targets are [Open: O-03] and are decided at Gate E [Source: 10]. The safety-semantic column is the automatic action on breach, and it is why the SLI is a capacity input: it determines whether load is shed, autonomy suspended or the platform stopped. All nine are capacity-relevant; none is excluded.

**The column that said "measurement point" is now two columns (F-03, blocking finding, closed here) [Committee].** v0.2 reproduced `slis.yaml` faithfully — but that file named a **component**, not a measurement, and when the SRE Lead reviewed v0.2 **exactly one of the nine emitted anything anywhere in the tree**. Left as it was, a Gate C reader would believe the baselines could be collected by running the system, and they could not. Instrumentation was step 0 of the reviewer's measurement order and has since been built for seven more (`observability/slis.yaml` now carries an explicit `emission_point`, `metrics` and `gap` field per SLI, and `docs/SLO_SLA.md` v1.2 records the same state): **eight of nine now emit, one does not**. Three limits apply to all eight and are not softened here: **every emission is in-process, unwindowed and unexported** — there is no trace-context carrier, no exporter and no telemetry backend, so nothing below can be joined or read across a deployed cell [Open: SRE-R4, SRE-R10 proposed]; **an emission point is not a baseline** — collecting one is Gate C work and **no baseline of any kind exists**; and **no deployment cell exists to collect one in** [Open: H-05]. The dangerous direction of each SLI is now **declared** in `slis.yaml` rather than inferred from the SLI's name, which closed F-07/SRE-R2 before any target could be set the wrong way round.
