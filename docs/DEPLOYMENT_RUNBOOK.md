4. Apply IaC change in the target cell; feature flags default off for new behaviour. **No cell is provisioned today and `infra/` contains no IaC module** — this step has no target until H-05 [Open: H-05].
5. **Bring the durable stores up in order and prove each one** (ADR-018, ADR-020): control store opens and `verify()` passes; audit store opens and its **chain** verifies; the anchor directory is reachable **and the published verification is called explicitly**. **A process that started is evidence of the chain check only — the witness is not checked at open**, so "it came up" never means "the witness is intact". Record the control-store journal rows, the audit chain length and the anchor count **at deploy**, so a later restart or drill has a before-figure to be compared against (INCIDENT_RESPONSE RB-14).
6. Deploy Control and Execution planes behind the executor lease (standby first, then lease transfer, then old active drained) — no in-flight order may be orphaned (TC-EX-004). Note that in-flight **intents** do not resume across a restart: the control-plane intent tracker and decision index are in memory, so a pre-restart intent is refused as unknown and its order can be cancelled but not resumed (ADR-018 §Consequences) [Open: R-05].
7. **Run the synthetic intent probe end to end and read the verdict against the id it returns** (`rt365 probe --env sim`). The probe now emits **one** correlation id from the first span to the audit row and prints it twice — `correlation_id` and `trace_correlation_id` — so a divergence between the id you are handed and the id the verdict was computed under is visible in the output rather than assumed away; the command exits non-zero if they differ, if any `missing_spans` remain or if any span is `failed` (F-14, TC-OB-006, TC-PKG-001). **Take the printed correlation id to the trace view and confirm the stages are under it** — that is the check, not the word "complete". `stages_not_reached` is a correct fail-closed stop (no order was authorised, so no `order_command` or `broker_ack` exists); `missing_spans` is a **defect and an incident**, never a warning (INCIDENT_RESPONSE RB-15). Two limits remain and are not closed by this change: the tracer is **in-process only** with no propagation carrier and no exporter, so trace completeness still cannot be checked **across** a deployed cell; and the alert path can now record a delivery time but **nothing acknowledges an alert**, because no notification component and no operator acknowledgement path exist. Treat a green probe as a smoke test **of one process**, not as evidence that a deployed cell is traceable [Open: R-05, SRE-R4, SRE-R5, SRE-R10].
8. Enable flags progressively per tenant/account; observe SLIs for the soak window. **Eight of the nine SLIs now emit in process** (control-plane availability, market-data freshness, signal latency, risk-decision latency, order-ack latency, reconciliation completeness, time-to-halt, alert delivery); `event_lag_ms` has **no emission point and cannot have one** until a producer and a consumer exist on the bus [Open: R-05]. Two cautions before any figure is quoted: every emission is **in-process, unwindowed and unexported** — there is no backend to observe them in, so "observe SLIs" means reading a registry inside one process (O-18 telemetry export, SRE-R4); and `alert_delivery_s` is emitted only when an acknowledgement is recorded, which nothing outside a test does today. Each SLI's exact limits are written per row in `observability/slis.yaml` (`gap:`) — read that file, not this line, before quoting anything. **No SLO target exists** [Open: O-03].
