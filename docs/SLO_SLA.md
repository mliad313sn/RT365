**Measurement readiness [Committee], read against the tree at `8f2258e`** (v1.1 recorded the state at `40bcb51`, when one of nine emitted). The "measurement point" column names the **component** an SLI belongs to; it has never named an emission point. Eight of the nine now have one, and each carries the limits of what it measures — the authoritative, per-SLI statement of those limits is the `gap:` field of `observability/slis.yaml`, which this table summarises and never softens. **Every emission is in-process, unwindowed and unexported: there is no telemetry backend, so none of these can be collected across a cell or read anywhere but inside the running process** [Open: O-18, SRE-R4]. Instrumentation was step 0 of the measurement order and it is now done as far as code can do it; **collecting a baseline is still Gate C work and no baseline exists**. Nothing here is a target and no target cell is changed [Open: O-03].

**Direction is a safety property, and it is now declared rather than inferred** [Committee] (F-07/SRE-R2, closed at `8f2258e`). `observability/rtobs/slis.py` used to infer which way a breach lies from the SLI's *name* — greater-than for names containing "latency", "freshness" or "lag", less-than otherwise — so `alert_delivery_s` and `time_to_halt_s` would have been compared **inverted** once a target existed: a fast halt breaching and a slow one not. Each SLI now carries a required `direction:` field, an SLI that omits it is refused at load, and the comparison is proved in both directions by TC-OB-009/TC-OB-010. This closes **before** O-03 by design: the first target set on an inferred direction is the first inverted alarm. **No target may be set from this seat: a target needs a measured baseline and business approval** (O-03) [Source: 10].
